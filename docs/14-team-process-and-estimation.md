# 14 Team Process and Estimation

## Delivery Model

Use short iterations with milestone-based planning.

## Team Roles

1. Product owner
2. UX and UI designer
3. Mobile engineer
4. Backend engineer
5. QA engineer

## Backlog Structure

1. Epics by major app area
2. Features by user outcome
3. Stories with acceptance criteria
4. Technical tasks linked to story

## Estimation Approach

Option A: Story points
- Good for velocity tracking over time

Option B: Ideal engineering days
- Easier for small teams with predictable cadence

Recommendation:
- Use story points for feature work and time-box spikes for unknowns.

## Definition of Ready

1. Story has user value and acceptance criteria.
2. Dependencies are identified.
3. API or UI contract is available.

## Definition of Done

1. Implementation complete.
2. Tests pass.
3. QA validation done.
4. Documentation updated.
5. Telemetry events reviewed when applicable.

## Planning Cadence

1. Weekly planning and backlog refinement.
2. Midweek risk review.
3. End-of-week demo and retrospective.
